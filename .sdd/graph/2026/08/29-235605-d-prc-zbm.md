One pre-flight evaluation decides every entry this repository captures, and the capture records that
it ran rather than repeating it.

`scripts/graph-capture.py` runs `sdd new --dry-run`, reads the severities out of that output and
refuses anything above low severity. The capture that follows passes `--preflight-verified`, so the
tool notes a pre-flight as run and clean instead of running its own. `--skip-preflight` stays unused,
since it marks an entry as one nothing ever checked.

A model backs the validator, so two evaluations of one draft answer independently. Two of them let an
entry capture carrying a medium finding the gate never saw, and that finding then sits in capture
output nobody revisits once the capture succeeds. One evaluation cannot disagree with itself, which
is the whole of the repair.

The rejected repair keeps both evaluations and refuses when the capture's own output carries a
finding above low severity. It acts too late. By the time that output exists, the tool has written
the entry and committed it. Nobody edits an entry's body, so the only remedy left is a superseding
entry, and the graph carries both from then on.

The accepted cost is a dependency on what the flag promises. A build offering no
`--preflight-verified` captures with no pre-flight flag at all, so the tool runs its own pass and the
entry lands the way any plain capture does. The script reads `sdd new --help` to tell which case it
is in.

The script behaves this way now, so nothing follows from this entry. Three checks confirm it. A
clean draft costs exactly one pre-flight evaluation. The script refuses a draft carrying a finding
above low severity, and captures nothing. A build without the flag still captures, and reports what
its second pass finds under the rule governing the first. Medium and high reach the caller, and low
never does.
