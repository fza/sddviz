sddviz runs on Wails v3 with a Go back end, and the desktop build allows cgo.

Three properties decide it. sdd is a Go project that documents an embedding seam, so a Go host
reaches it as a library rather than as a subprocess. No binary sits on `PATH`, and `go.mod` pins the
version. Go also carries a maintained YAML library, where every widely used Rust one now carries a
deprecation. Wails v3 builds the same code as an HTTP server, which makes a later web deployment a
second build rather than a second application.

Tauri v2 with a Rust back end loses on three counts. It offers a stable framework needing no cgo.
Against that stand a deprecated YAML ecosystem, an `sdd` binary the reader must install at a
compatible version, and a web deployment that means writing an HTTP server by hand.

Wails v2 loses as well. It carries the same Go gains on the release its maintainers call stable. Its
API belongs to the generation v3 replaces, and it builds no server, so a web deployment there means a
rewrite.

The accepted cost is maturity. Version `v3.0.0-beta.16` is a pre-release, and its maintainers name v2
the recommended stable release. The 3D view is indifferent either way, since both frameworks render
in the system WebView.

Nothing follows from this on its own. It constrains work other entries commission.
