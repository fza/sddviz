The back end parses an entry's YAML frontmatter with `serde_yaml_bw` 2.5 and a derived
deserializer. Splitting the frontmatter from the body below it needs no dependency at all.

It is the only live option on real semver, released 2026-08-15, and it is built around parsing
malformed input without panicking, which is the case that matters when the input is a stranger's
repository rather than a fixture written here. What the graph actually holds is undemanding: across
950 real entry files there is no block scalar and no multi-line value, only scalars, sequences,
nested maps, and single-quoted strings with doubled-quote escaping in 324 summaries.

`serde_yaml` is turned down despite 89 million recent downloads and the best understood behaviour of
any Rust YAML crate. It has been frozen since 2024-03-25 and carries `+deprecated` in its own
version string, so it receives no fix ever, including for a parse bug met in a reader's graph.

`noyalib` is turned down as the most recently released option and the crate `serde_yml` now forwards
to, because it sits at `0.0.x` with no semver promise and its download count measures the momentum
of a predecessor that was itself deprecated.

`saphyr` with hand-written mapping is turned down as well. It buys independence from every
serde-YAML fork and full control over how a malformed field reaches a reader, at the price of
noticeably more code for every field and `0.0.x` versioning on the parser too.

Nothing follows from this decision on its own. It constrains work tracked elsewhere rather than
commissioning any, and the dependency enters the crate manifest with the first code that reads a
graph file, under whichever entry commissions that work.

The accepted cost is exposure: 116 thousand recent downloads is the smallest of the live options, so
it is the least exercised at scale and one maintainer carries it.
