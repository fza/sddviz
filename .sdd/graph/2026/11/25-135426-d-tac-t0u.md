Copies of sddviz handed to someone directly get a Developer ID signature and Apple notarization on the owner's Mac. The GitHub release and the Homebrew cask stay as they are. The owner now holds a Developer ID Application certificate for team `4PZ48PNC93`. That removes the premise behind the accepted Gatekeeper cost in the cask release decision (20261024-025546-d-tac-hvx). The cask keeps its route all the same: it still clears the quarantine flag and signs ad hoc.

A shared copy comes from one command in `source/`, with `SDDVIZ_SIGN_IDENTITY` naming the Developer ID Application identity:

`task darwin:sign:notarize`

The task builds the bundle, signs it with the hardened runtime, and submits a zip to Apple through the keychain profile `sddviz-notary`. It waits for Apple's verdict and staples the ticket to `source/bin/sddviz.app`. `ditto -c -k --keepParent` then zips the bundle for sending. The profile holds an app-specific password and lives in the owner's login keychain, never in the repository.

A shared copy holds `arm64` alone, the chip of the Mac that builds it. A recipient on an Intel Mac cannot open it, so the sender checks the recipient's chip first.

Rejected: signing in the GitHub release job. It puts the certificate's private key and a notary API key into repository secrets. GoReleaser then has to sign the bundle before archiving it and ship a zip or a disk image, since a `tar.gz` carries no stapled ticket. Also rejected: a universal build through `package:universal`, which doubles the build time and the bundle size of every shared copy.

The first run passed. Apple accepted the submission, `stapler validate` passed, and `spctl` accepted a copy unzipped with a quarantine flag set, reporting `Notarized Developer ID`.
