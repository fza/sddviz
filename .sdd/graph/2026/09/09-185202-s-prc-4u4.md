One rule points to the wrong place for the search index. A reader who trusts it looks in the wrong
tree.

`AGENTS.md` line 78 lists what belongs to sdd rather than to the viewer. It calls one of them "the
vector index under `.sdd/index/`". No checkout holds such a folder. The graph at
`/Users/felix/Codepot/devops/format-d-fdbox` has none. sdd's own tool keeps its index in the
machine's cache instead, keyed by who the graph is and by which embedder built it.

## What it costs

That line sits beside the rule that the viewer may not write to a graph it reads. A reader weighing
whether reading the index breaks that rule reads that it lives inside a checkout. They conclude that
it does. They then drop a thing the rule never barred. The viewer already reads that index, so the
line as written describes what the code does not do.

A second reader takes the other lesson. They go looking for `.sdd/index/` to explain a missing
result, find nothing, and trust the rest of the page less.

## What closes it

The line names the machine's cache, keyed by who the graph is and by which embedder built it. It says
plainly that reading or filling it touches nothing inside a checkout. Nothing else on that line
changes: status, search across its modes, and linting all still belong to sdd.
