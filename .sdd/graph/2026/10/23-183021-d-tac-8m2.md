The viewer embeds the sdd fork at `github.com/fza/sdd` release `v0.18.0-alpha.2.fza.24`, and names each entry by the `title` that build writes.

## What changes

`source/go.mod` keeps the module path `github.com/networkteam/sdd` and adds a `replace` pointing it at `github.com/fza/sdd v0.18.0-alpha.2.fza.24`. The fork's repository is public, so a build needs no private access.

The work then follows the fork's API.

- Imports move to `pkg/application` and `pkg/local`.
- The store implements the smaller `GraphStore` port, which holds `Current` and `ReadAttachmentPage` alone. The write methods the store used to refuse leave the type, so no write method exists to call.
- Search moves to the embedding types in `pkg/llm/embed` and the `PrepareSearch` option of `ApplicationOptions`.
- Fresh output from the fork replaces the rendered sdd output under `source/internal/graph/testdata/rendered/`.
- The entry record gains a `Title` field, sent to the front end as `title`. The store reads it from each file's `title` key, the same way it reads `summary`. An entry without one carries an empty title.
- The front end names an entry by its title wherever it names one: the table, the graph, the panel, and every list of links. It falls back to the summary when the title is empty.
- `docs/index.md`, `AGENTS.md` and each version note in the code name the fork's release in place of `0.16.2`.

## Why

A short name has to survive every rewrite of an entry and reach every reader of the same graph. Only a field sdd itself writes does both. The fork writes one for every entry and migrates a graph to schema 2 to carry it. Embedding the same build also lets the viewer read the schema this graph states.

## Rejected

- Reading `title` from the file while still embedding `0.16.2`. It is cheap, but the viewer would read a field its embedded sdd does not know.
- Cutting a name from the summary's first sentence. Summaries open with long claims, so the name stays long.
- A title cache the viewer keeps itself. Each machine would hold its own answer.

## Accepted costs

- About a thousand lines of Go change, mostly the store, search, and the embedding seam.
- The viewer depends on an alpha build of a fork. Graphs written by upstream sdd carry no title and keep showing summaries.
- The record shape the front end receives changes, and so does `docs/index.md`.

## Acceptance criteria

- `go.mod` carries the `replace`, and no import names the old `application` or `local` paths.
- The store type has no write method, and the `sddtest` read checks that apply still pass.
- Vector search and term search both answer against this repository's graph.
- Every rendered fixture comes from the fork, and the tests reading it pass.
- `Entries()` returns `title` for each entry in this repository, and an empty title for a file without one.
- The table, the graph, the panel and the link lists show the title, and show the summary when it is empty.
- `devbox run test` and `devbox run lint` pass, and no document or code note names `0.16.2` as the embedded version.
