The viewer embeds the sdd fork release `v0.18.0-alpha.2.fza.24` and names every entry by its title, in commit `6c39425`.

## What landed

- `source/go.mod` replaces `github.com/networkteam/sdd` with `github.com/fza/sdd`, and imports read `pkg/application` and `pkg/local`.
- The store carries no write method. The access resolver refuses write access and every session.
- The embedder answers the fork's `embed.Embedder` port and passes `sddtest.RunEmbedderTests`.
- The rendered fixtures come from the fork's own CLI, and the fixture entries are the titled files this graph holds.
- `Entries()` returns `title`. The table, the hover text in the graph, the panel heading and the link lists show it, and the summary stands in where a file has none.
- `docs/index.md`, `README.md`, `AGENTS.md` and `source/AGENTS.md` name the fork release.

## Beyond the decision

The fork keeps embedding settings in `$XDG_CONFIG_HOME/sdd/config.yaml`, beneath both repository files. The viewer now reads that file in the same order, so vector search answers on a machine that configures it there alone. `graph.UserConfigPath()` names the file, and `NewService` takes it.

The committed `.sdd/config.yaml` may no longer name an embedding `endpoint` or `api_keys`. Without that rule, a repository's committers could name a server that receives the key from a reader's machine.

## Checked

Every acceptance criterion holds. Against this repository, all 29 entries carry a title, one word searches over terms, and a phrase searches the vector index. Each new guard failed its own test when broken and passed once restored. `devbox run test` and `devbox run lint` pass.
