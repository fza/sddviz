A machine working on this repository installs Vale and sdd from the `fza/tap/vale` and `fza/tap/sdd`
casks. `scripts/dev-setup.sh` installs both and counts a command as absent unless its version carries
the `fza` mark, so an upstream build on `PATH` reads as missing rather than as present.

The Vale fork reads a source file as code and lints only its comments, which upstream does not do.
The script no longer builds that fork from a pinned release. A cask ships the release already
built, and moving to a newer one is `brew upgrade` rather than an edit here. The sdd command line has
to be the fork as well, because `agentic-capture` refuses any other build.

Vale `v3.25.1-fza.2` reads `.vale.ini` sections against relative paths alone. Handed an absolute
path, it skips every carve-out and lints `.sdd/` and `.claude/` as prose. Every caller here therefore
passes a path relative to the repository root: `.claude/hooks/vale_new_prose.py`,
`scripts/lint_draft.py`, and anyone following `AGENTS.md`.

The same release reports a bare identifier opening a comment as a spelling error. Thirteen comments
under `source/frontend/src` now open with the identifier in backticks, which `AGENTS.md` already asked
for.

The path check in `scripts/lint/refs.py` skips a fixture graph under any `.sdd/` directory, since its
entries name paths as they stood at capture and nobody edits them.

The rejected alternative pins the Vale version in the script as the source build did. A cask carries
no pinned older release, so a pin could only refuse a machine that upgraded.

Acceptance:

- `scripts/dev-setup.sh --check` reports nothing on a machine carrying both casks, and names `vale`
  or `sdd` when the command on `PATH` lacks the `fza` mark.
- The prose hook passes a file under `.sdd/` without a finding, and reports a finding on a new
  Markdown file outside the carve-outs.
- `devbox run lint` passes under Vale `v3.25.1-fza.2`.
