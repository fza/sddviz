The devbox environment now sets `GOROOT` to an empty value, so the pinned Go toolchain always compiles against its own standard library.

A second Go install can leak its own `GOROOT` into the shell. The pinned Go 1.26 then reads the standard library of that other version and refuses to compile with `compile: version "go1.27.3" does not match go tool version "go1.26.5"`. An empty `GOROOT` makes Go fall back to the root it ships with.

The `env` block of `devbox.json` carries the setting, and commit `c2034cb` lands it. It covers both ways into the environment. Entering the directory through direnv exports the empty value, and `devbox run` applies it too.

A clean shell with a foreign `GOROOT` proves the fix. With the setting, `devbox run` passes `go vet`. Without it, the same run fails on the version mismatch.
