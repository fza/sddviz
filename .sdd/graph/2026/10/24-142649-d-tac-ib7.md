A dependency bump releases a patch. In `.releaserc.yml`, semantic-release counts a `build` commit scoped `deps` or `deps-dev` as a patch, and its notes list such a commit under Dependencies. Commit `46bc71e` carries the rule.

Dependabot writes those two scopes. A bumped front end tool such as vite builds the bundle that ships, so the bump changes what a user installs and earns a version. Without the rule, semantic-release releases nothing on such commits, and a run by hand from `main` reports no relevant changes.

The rejected option was pushing each such version by hand, as with `v0.0.1`. It needs a pushed version per dependency release, and GoReleaser alone writes those notes. The accepted cost: every Dependabot merge yields a patch on the next run by hand, even one changing only a test tool. A dry run plans `0.0.2` with the vite bump under Dependencies, and plans nothing with the rule removed.
